# 2026-10-07 合理性复核：当前方案不能直接开跑

复核对象：2026-10-05 v1，原提交 5090b5875ff9b1a91b87a62f87c737672c0a4aa3。当前没有任何火焰模型实验结果。本次只进行了论文/仓库/数据元信息检查，以及无模型、无数据拟合的解析计算。

## 结论

**管理框架合理，科研方案仍需修订；上次称为“可执行计划”过早。**

- 方向一的研究问题有价值，但“困难背景原型 + DINOv3”不足以单独构成创新。条件性保留，需要补入 INSID3 对照、纠正 FSSDINO 适配、明确标注成本和统计目标。
- 方向二的当前唯一候选 g×l 不建议作为论文主方法启动。它与已有火灾全局/局部验证研究高度接近，而且乘积不是一致性度量。可以视为廉价基线，但目前没有足够理由为其投入正式实验预算。
- 两方向均未通过论文项目的开跑审查。保持 NOT_STARTED，新增 execution_ready=false；此次文献审计不是模型失败，不虚构已执行两轮验证，也不消耗换方向次数。
- “方向一失败只换一次方向二，再失败立即停止”保持不变。若方向二在正式前置审查仍不合格，则直接停止，不必为了用满次数强行跑模型。

## 2. 方向一的实现与比较问题

### FSSDINO 的原说明有事实错误

已检查作者 commit 24858986ea55e312200079937989ad32360f09b2 的：

- [configs/dg.yaml](https://github.com/hussni0997/fssdino/blob/24858986ea55e312200079937989ad32360f09b2/configs/dg.yaml)：真实路径是 dg.yaml，ViT-B/16、512 输入、n_clusters=5；并非不存在相关配置。
- [fssdino/module.py](https://github.com/hussni0997/fssdino/blob/24858986ea55e312200079937989ad32360f09b2/fssdino/module.py)：类相似图融合后通过 argmax 得到标签；pixel_scores 为各类分数的最大值，**不是火焰前景概率**。
- [fss_eval.py](https://github.com/hussni0997/fssdino/blob/24858986ea55e312200079937989ad32360f09b2/fss_eval.py)：使用上述类别 mask 评价。

因此，不能把 pixel_scores 放进原 0.05…0.95 网格直接当火焰概率校准。应区分原生 FSSDINO 标签结果与显式导出 fire/background margin 的校准适配版；后者必须独立命名，冻结映射和单元测试后才能比较。本轮只纠正说明，不伪造已经完成的适配器。

### “5-shot”不等于只有五张标注

原方案每次用 5 张支持 mask，但另外有 ≥30 张有火校准 mask、≥60 张无火标签；三个支持种子也涉及一个更大的已标注池。应明确称为“5 个支持样本 + 额外源域有监督校准”，报告支持池、实际使用数和校准标注数。不能与严格仅五张标注的方法不加说明地比较。

### 必须补强但不能无限加基线

预定核心对照保持单原型、多原型、FSSDINO，额外补入官方 INSID3。INSID3 的骨干和输入设置需公开列出：同骨干同分辨率的适配比较不能冒称官方默认复现；官方默认是更大骨干、1024 输入，不能照搬论文分数到本数据上。

困难背景筛选还可能丢掉普通背景覆盖，使其他场景误报更高。假设不能预设为一定有效。要把“困难背景抑制”和“位置偏置消除”区分开；否则观察到改善也不能说明提出了新的火焰机制。

支持 mask 经 patch 占比 ≥0.8 过滤可能让小火焰没有有效前景。必须在盲态数据检查时登记有效 patch 数；不足 K 时按预定技术失败处理，不看测试结果再换阈值或裁剪。

## 3. 方向二的概念与数据问题

### 乘积只是一种融合分数

g=l=0.5 与 g=1、l=0.25 的乘积均为 0.25，但两种情况的一致程度明显不同。相同模型的全图与裁剪也不是独立证据。因此当前 C 应叫“全局—局部乘积分数基线”，不能称为校准后的联合概率、因果视觉证据或已实现的一致性检验。

如果以后保留该问题，必须在正式模型运行前定义它比 FireMAS、多视图均值和普通阈值调整额外解决什么。当前审计没有确认这种贡献，不新增模型或候选公式进行试错。

### SAFIRE 没有直接给出独立事件 ID

实际调用[官方数据查看接口](https://datasets-server.huggingface.co/first-rows?dataset=RISys-Lab%2FSAFIRE_193K_mcvqa&config=mcqa&split=test)，公开 schema 包含 image、image_name、scenario、question、options、answer、answer_key；没有原计划暗示可直接读取的 image_id、video_id、event_id。

应该用 scenario + image_name 建内部 ID，再用图像哈希核对冲突；来源事件需额外追溯。去重簇只能称“推定独立图像簇”，不能自动升级为独立火灾事件。第一条公开记录就是图形化烟花类别，证明真实照片筛选确有必要，但一条样例不能估计全库比例。

因此“800 个独立组都已可用”尚未得到证明。问答数量不是可用二分类样本量。即使 100 张审计只发现 5 张错误，也不能证明总体误标率 ≤5%；应同时报告二项区间，并说明审计只是排雷。

### 源域校准不是跨域召回保证

在 DFire 上选择经验召回 95% 的阈值，不保证 SAFIRE 仍有 95% 召回，更不代表部署安全保证。[Neyman–Pearson 分类原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC5804623/)也依赖明确的分布与独立样本条件。这里跨域评测应被表述为检验该阈值的迁移效果。

五个视觉视图也不必然等于五次底层 forward：Yes/No 序列打分的实现可能重复前缀或视觉编码。吞吐预算应按真实完整打分路径测量，不按视图数直接推算。

## 4. 门槛严格不等于统计设计充分

下述数字是解析敏感性检查，**不是模型实验、实际方差或正式功效保证**。推导与可重算脚本见[design_sensitivity.py](../../code/flame-research/design_sensitivity.py)。

- 对单个预定 IoU 比较，取单侧 α=0.05、目标功效 80%、真改善 0.03，近似 n = ((1.645+0.842)×配对差值标准差/0.03)²。标准差为 0.10 / 0.15 / 0.20 时，需要约 69 / 155 / 275 个独立有火组。
- BoWFire 总共只有 119 张有火图，1:1 拆分后确认阶段约 59–60 张，且去重后可能更少。在标准差假设 0.15 下，59 张对单一比较的近似功效仅约 46%。原方案还要求超过所有基线并满足多项门槛，实际联合通过概率不能由这 46% 代表。
- 方向二若要检出 FPR 降低 0.05，配对预测不一致率假设为 0.05 / 0.10 / 0.20 时，近似需要 118 / 242 / 489 个负组。固定 200 个并非普遍足够。
- 200 个有火组中，若两方法不一致率为 4%，零召回差附近的单侧 95% 正态误差宽度约 2.33 个百分点。因此“观测下降不超过 1 个百分点”不能被写成统计上证明了 1 个百分点非劣效。

原有门槛还有比较逻辑问题：一个跨域后几乎从不报警的基线，FPR 可以为 0，但它的召回也可能很差。要求候选对“每个基线”都再降低 5 个百分点，会使任务逻辑上不可通过。应在冻结前确定共同工作点、主要比较对象、最低召回要求和辅助比较，不能在看到目标结果后挑基线。

**本轮不私自降低 3/5 个百分点门槛，也不增加样本预算。** 这些数字保留为 v1 草案记录，但不能视为已经验证的正式判据。合理修订应将小样本阶段定位为可行性筛查，并在同一预算内先确认检测能力；无法支撑主张就前置退出，不做结果出来后的扩样或调参。

## 6. 保留的管理措施与下一步边界

保留：非 YOLO、冻结模型优先、公共数据、预先冻结配置、分组去重、独立确认、一次切换、两次不达标停止、10 工作日/40 GPU 小时硬上限。

在任何正式运行前，仅完成一份固定的关闭问题清单：

1. D1：明确相对 CoW、INSID3 和 Inverse-INSID3 的实际贡献；若只能剩“换成火焰数据”，前置不通过。
2. D1：完成 FSSDINO 分数适配定义和 INSID3 对照协议，完整登记有监督校准成本。
3. 共用：依据真实可用独立簇数，冻结单一主要比较及其统计能力说明；不得依赖目标模型结果估方差后循环扩样。
4. D2：证明相对 FireMAS 的具体差异并给出可证伪主张；当前乘积公式不满足此条件。失败就淘汰该候选。
5. 共用：补齐数据下载、分组、权重、GPU 与吞吐记录；不能把 40 小时预算写成已证明可按时完成。

以上是开跑条件，不是追加实验任务。此次没有选第三方向、启动训练或重置试验次数；也没有把两份草案包装成已达到中科院二区论文水平的方案。
